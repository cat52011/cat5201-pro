## 一、開跑前（三件事，各一分鐘）

1. **把每日花費上限調高**到足以跑完九次。被上限擋掉的那一次要作廢重跑，並記在下面的異常欄。
2. **開一個乾淨的專案檔**，存成 `eval-T01-20261029`。
   這個專案檔只放這九次，不要混別的工作——混了也不會算錯（提示詞對不上的節點會被略過），
   但清乾淨比較好查。
3. **記下程式版本**：在 repo 根目錄執行
   ```bash
   git rev-parse HEAD
   ```
   把輸出貼到本檔最後的「執行紀錄」欄。

```
研究台積電最近一季財報與近期股價表現，列出關鍵數字與可信來源
```

## 三、九次怎麼跑

每一次都是：**開一個新節點** → 貼上題目 → 設定好組別 → 執行 → 等它跑完。

> **一個節點只跑一次。** 重跑同一個節點會把上一次的產出蓋掉，
> 那一次就永遠回不來了（工具會警告，但資料已經沒了）。重複請開新節點。

| 次序 | 組 | 設定 | 節點數 |
|---|---|---|---|
| 1–3 | **A** | 關閉自動選模型（手動），模型固定 **GPT-5.5** | 3 個新節點 |
| 4–6 | **B** | 關閉自動選模型（手動），模型固定 **Claude Sonnet 4.6** | 3 個新節點 |
| 7–9 | **D** | 開啟自動選模型（**API Auto**） | 3 個新節點 |

組別不用你填，也不用你記在哪裡——`ingest` 會從存檔的「選模型方式 + 實際模型」自己推：
`API Auto` → D、手動 + GPT → A、手動 + Claude → B。
所以**唯一要做對的事是把開關設對**，其餘交給工具。

跑完九次之後：**存檔**（Ctrl+S 或存成同一個檔名）。

## 四、跑完之後交給我

把專案檔的完整路徑告訴我就好，預設會在：

```

```

我會跑這三步，然後把結果寫進報告：

```bash
dotnet run --project tools/EvalScorer -- ingest --run docs/eval/runs/2026-10-29 --project "D:\desk\college\cat5201-pro\file\eval-T01-20261029.json"
dotnet run --project tools/EvalScorer -- score  --run docs/eval/runs/2026-10-29
dotnet run --project tools/EvalScorer -- blind  --run docs/eval/runs/2026-10-29
```

- `ingest`：從存檔讀出九份產出與客觀欄（實際 token、逐筆加總的 USD、耗時、模型鏈）。
  **成本不是抄顯示字串，是把 `UsageRecords` 的每一筆實際金額加起來**，所以可以被重算。
- `score`：套上已凍結的必要內容清單，算字樣命中率與必備項齊備率。
- `blind`：產生代號檔與空白評分表，給兩位非作者評分（事實正確率只能由人判）。

## 五、你自己要注意的三件事

1. **跑的時候不要同時做別的事。** 耗時是本實驗的一個指標，背景在跑影片生成會汙染它。
2. **每一次跑完看一眼決策視窗**。如果某一次出現降級、重試或失敗，記在下面；
   失敗的那一次會被 `ingest` 自動略過（算不出完整產出的資料留著只會汙染平均）。
3. **D 組可能會彈出產出確認框**。T01 不該產生檔案；若彈出來，選「否」，
   這題要的是文字答案。若你選了「是」，那一次的成本就不可比，請作廢重跑。
