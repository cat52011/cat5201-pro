# 多模型協作 Eval 計畫(#22 / P3-20)

> 目的:用可重複的數據回答「**多模型協作是否優於單一模型**」——這是產品的核心宣稱,
> 學長與 Codex 都獨立點名。結果同時供:①商業敘事(值不值多花的錢/時間)②研究所申請(可寫成小論文/作品集實驗)。
> 執行成本估計:30 次執行 × 平均 NT$3~6 ≈ **NT$100~200、約 2~3 小時**(可分多天,注意每日上限設定)。

## 一、對照組(每題各跑一次,共 3 組)

| 組 | App 設定 | 代表 |
|---|---|---|
| A | 手動模式,固定 **GPT-5.5** | 單一 GPT |
| B | 手動模式,固定 **Claude Sonnet 4.6** | 單一 Claude |
| C | **API Auto**(多代理/多模型鏈,含 Perplexity 研究) | 你的產品 |

規則:同一題三組**同一天跑**(即時資料類避免跨日不公平);每組跑完記錄決策窗的 token/成本/耗時;
產出檔(PDF 等)三組都開「產生」,讓比較包含交付物品質。

## 三、評分(每題每組,盲評)

**盲評法**:輸出先去識別(存成 A1.txt/B1.txt/C1.txt,檔名只有代號),隔天自己評,或請同學/學長評更有力。

| 維度 | 1~5 分 | 錨點 |
|---|---|---|
| 事實正確 | 5=抽查 3 個數字/事實全對;1=有明顯錯誤或幻覺 |
| 來源可查 | 5=關鍵主張都有可點開驗證的來源;1=完全沒有 |
| 指令遵守 | 5=格式/字數/語氣全照要求;1=偏題 |
| 交付品質 | 5=可直接交出去用;1=要大改 |

**客觀欄(從決策窗抄,不用評)**:實際 tokens、NT$ 成本、耗時、用了哪些模型。

## 五、分析與結論模板

1. 四個維度各算三組平均分;C 組另算「每分品質的成本」(總分 ÷ NT$)。
2. **預期誠實結果**:C 在「來源可查」「事實正確」(研究類題)明顯贏;寫作/翻譯類(5、6)可能單模型就夠——這不是壞消息,是「什麼任務值得多模型」的分流依據,產品可以據此自動降級省錢。
3. 結論寫成一句話:「多模型協作在 __ 類任務上,以 __% 的額外成本換得 __ 的品質/可查性提升;在 __ 類任務上單模型已足夠。」
4. 這句話就是:給學長的答覆、簡報第 4 頁的數據支撐、研究所 SOP 的實驗段落。

## 六、注意事項

- 跑之前把「每日花費上限」調到 NT$300 以上,免得中途被擋。
- 陷阱題(10)三組的差異最值得截圖——誠實說不知道 vs 編造,是「可稽查」敘事的最佳素材。
- 全部截圖決策窗,尤其 C 組的多模型軌跡——這些是論文/簡報的一手材料。
