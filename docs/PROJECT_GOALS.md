# cat5201-pro 專案目標(North Star)

> 這份是「使用者親口說過的專案目標」，作為 pro(強化版)的北極星。
> 畢業版已凍結(tag `v1.0-graduation`)；本資料夾 `cat5201-pro` 為後續強化版。
> 建立於 2026-06-27。

---

## 🎯 整體定位

- 這是一個 **「AI 工作台 / 工作區」產品**，不只是聊天畫布。
- 是 **目前市面上沒有、且有實際用途** 的工具。
- 本質是 **「連接各個模型」的編排層**——多數功能不是它本身的，而是串接各家模型(圖片、影片、搜尋…)的能力。

## 🔀 雙重目標(明確要「都要」)

1. **畢業專題**:證明實力、能交件。
2. **真正商業化**:把這產品做到 **專業級水準**(第二步)。

## 💰 商業化的具體想法

- **使用者自備 API 金鑰(BYO-key)**。
- 盈利:**免費(靠廣告或買斷)** 或 **超低價訂閱**。

## 🧩 功能 / 方向目標

- **手機也能即時看到、甚至操控或使用** 此程式(列入未來規劃)。
- **Google 生態整合**(Drive / Docs / Sheets)——當初選 Gemini 的主因。
- 加入 **Gamma**(簡報設計引擎)。
- 加入 **Kling I2V**(圖 → 影片)。
- 原本構想:先把 **Google / Gamma / Kling** 加進去，再打包成「第一版」。

## 📋 原始路線圖目標(來自 docs / Codex 規劃，已採用)

**2026/9 商用級 MVP**:多模型路由、多代理編排、工作流、自動下游節點、檔案/圖片/影片生成、記憶、可稽查 UX、成本控制。
(詳見 `docs/PRODUCT_ROADMAP_2026-09.md` 的 Scope Tiers 與 §1–§18)

## ✅ 已決定方向(2026-07-02)

**商業化方向：往 ①開公司 + ③indie 走(走商業/web 路線),但先不收窄。**
**產品形態：「一個核心 × 三介面」—— 桌面 app 照舊能用、web 能用、手機也能用,三者共用同一套核心。**

- 唯一可行架構＝把執行/編排/工作區核心從 WPF 抽成 `cat5201.Core`(UI 無關)+ 可呼叫 API;桌面 WPF/web/手機都是呼叫它的前端。
- 紀律：這段「不收窄」的時間**只投在「任何垂直都通用的 web 化地基」(搬核心出 WPF、可測試、可遠端、observability),不再長橫向功能**,否則滑回「什麼都做」。
- ②作品進業界未選為主攻;WPF 全棧仍是畢業作品/原型,不丟棄(變成核心的桌面前端)。
- 已起步：建立 `cat5201.Core`(net8.0 無 WPF),搬入共用 DTO;§17 手機鏡像 DTO/指令/Kestrel + IAgentHost 是這條路的頭幾塊磚。詳見 STRATEGY §9 與記憶 one-core-three-surfaces。

> 待定(§9b 細節,核心可呼叫後再定):web 前端棧(React Flow / Blazor、TS / C#)。原三選一保留於下供回溯：①開公司(收窄垂直+web) ②作品進業界(WPF 全棧加分) ③indie(窄功能+web+訂閱)。

## 🧭 與目標相關的關鍵結論(供決策參考)

- **真正難抄的差異點 = 「終端使用者 × 每步可稽查」** 的交集，不是「多模型多功能」(那層最廉價、最可抄)。
- **BYO-key ⟂ 面向非工程師**:BYO-key 對工程師低門檻、對非工程師是高牆(要開 4 個平台帳號)。市場證據:BYO-key 工具(TypingMind/Msty/BoltAI)全是技術小眾;非工程師大眾要的是代管(Poe $20/月)。
- **能同時要的結構**:免費 BYO-key 層(衝採用/履歷)→ 付費代管層(代管 key + 團隊/SSO/合規稽查 = 真營收)。
- 值得拆的競品:**TypingMind**(BYO-key 買斷範本)、**Msty**(桌面 BYO-key freemium)、**Dify**(畫布 + 正確變現階梯)。
