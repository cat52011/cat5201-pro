> 其餘的判斷（版面好不好看、答案合不合理）本來就是人的工作。

> **開始前**

## C. 連線與匯流 ★★

> **這一區以前做不出來。** 從連接點拖出去**一律會生出一個新節點**，而右鍵「變更上游節點」
> 是把既有那條線**搬走**、不是多加一條——所以一個節點永遠只有一個上游，
> 菱形根本畫不出來。排程器早就看得懂「等所有上游都跑完再開始」（`FlowSchedule`，有單元測試），
> 畫面上卻永遠產不出那個形狀。現在補上了。

### ☐ C-1 連接點說得出自己能做什麼 ★★
- ☐ 滑鼠停在節點**左上或右上那顆灰色小圓點**上 → 游標變成手指，出現提示：
      「往空白處拖＝新增一個下游節點／拖到另一個節點上＝把那個節點接成下游…」

### ☐ C-2 拖到空白處＝新增節點（原本的行為，不可壞）
- ☐ 從小圓點往空白處拖放開 → 生出一個新節點並自動連好、進入編輯狀態

### ☐ C-3 拖到既有節點上＝接起來 ★★
- ☐ 拖曳途中把游標移到**另一個節點上** → 虛線**變成藍色**（代表放開會接起來）
- ☐ 移回空白處 → 虛線**變回灰色**
- ☐ 放開 → 兩節點之間出現一條**藍色虛線（流動連線）**，不是生出新節點
- ☐ ⚙ 拖回**自己** → 沒有反應，只有提示音
- ☐ ⚙ 拖到**已經連過**的同一個節點 → 沒有反應，只有提示音（不會疊兩條線）
- ☐ ⚙ 拖到自己的**下游**（會形成環）→ 沒有反應，只有提示音
      （含隔了好幾層的後代；規則在 `ConnectionRules`，9 項自動化測試）
- ☐ 右鍵那條新線 → 可以改回灰色一般連線，再右鍵又變回藍色
- ☐ **藍色虛線的空隙處也右鍵得到** ★★（沒有「點到透明區塊就沒反應」這回事）
- ☐ 滑鼠停在虛線的**空隙處**也出得來提示文字
- ☐ 滑鼠停在整條線上都是**手指游標**
- ☐ 關程式再開 → 連線與它的流動狀態**都還在**

### ☐ C-4 匯流菱形 ★★

照 C-3 的方式接出 **A → B → D** 與 **A → C → D**（四個節點、四條線，全部是藍色虛線）：

1. 建節點 A，貼入下面第一段提示
2. 從 A 的小圓點往空白處拖兩次 → 生出 B、C，各自貼入提示
3. 從 B 的小圓點往空白處拖一次 → 生出 D，貼入提示
4. **從 C 的小圓點拖到 D 上放開** ← 這一步就是以前做不到的

A：
```
列出 2026 年台灣電動機車市場的三個關鍵趨勢。
```
B：
```
針對上面的趨勢，列出對消費者的三個影響。
```
C：
```
針對上面的趨勢，列出對製造商的三個影響。
```
D：
```
把上面兩份影響分析合併，寫成一段 200 字的總結，分別點名消費者面與製造商面。
```

- ☐ 從 A 執行整條鏈
- ☐ **D 要等 B 和 C 都跑完才開始**（不是誰先完成誰就觸發）★★
- ☐ **實際打開 D 的輸入內容**，裡面同時有 B 和 C 的結果 ★★
- ☐ D 的輸出真的同時講到消費者面與製造商面
- ☐ D 只執行一次
- ☐ 讓 B 失敗（清空它的提示或暫時斷網）→ **D 不執行，也不會卡在琥珀色「等待中」**
- ☐ 線性鏈 A → B → C 仍然正常

### ☐ C-4b 分兩次手動跑，匯流照樣會接上 ★★

這是 10/13 回報的「上游跑完了最下游卻不跑」。原因是匯流只看**這一輪**的完成名單：
手動跑完 B 再手動跑 C，兩次執行各自只知道一半的上游，D 永遠停在等待，而且畫面上沒有任何訊息。

用 C-4 的四個節點，但**不要**從 A 跑整條鏈：

- ☐ 只把 B→D、C→D 兩條線改成藍色虛線（A→B、A→C 維持灰線）
- ☐ **手動單獨執行 B**，等它跑完 → D 還不動（正確，C 還沒有結果）
- ☐ **手動單獨執行 C** → **D 自己開始跑** ★★
- ☐ D 的輸入裡 B 和 C 的結果都在
- ☐ 反過來先 C 再 B，結果一樣

再驗一次「舊結果不能充數」：

- ☐ 改掉 B 的提示，**從 A 執行整條鏈**（先把四條線都改成藍色虛線）
- ☐ D 要等 B **重跑完**才開始，不會拿 C 上一輪的舊結果提早跑

### ☐ C-5 變更上游（原本的行為，不可壞）
- ☐ 節點右鍵 →「變更上游節點」→ 點另一個節點 → 原本那條線改接過去（**不是**多一條）
- ☐ 按 ESC 取消 → 原連線完好如初

### ☐ C-6 下游繼承上游文件
- ☐ 上游產出一份 docx，下游節點輸入「把上面那份報告濃縮成 5 條重點」
- ☐ 下游真的讀得到那份文件的內容

## 已知限制（不是 bug）

- **本機記帳不可能精確。** 四家都沒有查餘額的 API；圖片按張、影片按秒都是估算；
  OpenAI 的內建工具費（web search $10/千次、file search $2.5/千次、
  container $0.03–1.92/20 分鐘）官方**不在 usage 回報**，記不到。
  能做的是讓誤差看得見、被對帳吸收，而不是精確。
- 匯率是約略固定值（US$1 = NT$32 = A$1.52 = €0.92 = ¥155 = £0.79），不是即時匯率。
- `gpt-5.6-sol` 的長上下文級距（input > 272K 變 $8/$30）目前一律照 $4/$20 算；
  一般任務不會到 272K，超長文件分析會低估。
- 圖片價目用官方「輸出費用」估算表 + 提示詞的文字輸入；
  參考圖（image-to-image）的影像輸入費沒有另算。
- Anthropic 沙盒時間每月 1,550 小時免費、超過 $0.05/小時，不計。
- 文件技能的 100 秒是「**完全沒有動靜**」才算，不是「這輪要在 100 秒內跑完」。
- 餘額扣成負數是刻意的（帳要留真的），畫面顯示 0 並另外提示超出多少。
- 中止的串流只能**估算**伺服器已經生成多少（以時間 × 典型輸出速率推算），不會精確。
- 最佳品質模式**不是預設**。它仍然留在個人化裡，等它穩定了再把預設換回去。
- 附件文字總量上限 25 萬字、文件技能的主要內容上限 12 萬字，超過會截斷並明說。
- 配圖判斷是純規則（看大綱內容），不另外呼叫模型——多一次來回就是多幾秒與多一筆錢。
  兩邊訊號都沒有時不配圖：生成圖是最貴也最慢的一步，看不出來就不該自己花這個錢。
- 右下角快捷面板一律美元、設定頁用各服務原幣別，是刻意的：
  前者要能並排比較，後者要跟官網帳單對得起來。
- LibreOffice 不更新 Word 的目錄欄位；Word 會。
- 表格圖表只在「有文字類別欄 + 可加總數字欄 + 2～20 列」時產生。
- 百分比欄沒有合計，刻意的。
- 記憶重點萃取只在「手動加入記憶」時呼叫模型；自動記憶走規則版。
- 匯流節點在上游失敗時不會執行，刻意的。
- 拖到既有節點上建立的連線**預設是流動連線**：會特地把兩個現成節點接起來，
  意思通常就是「這個跑完換那個」。不想要的話右鍵那條線可以改回一般連線。
- 超支授權只涵蓋**那一次執行**；同一天的下一個任務會再問一次。
