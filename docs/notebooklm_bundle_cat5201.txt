【一、專案定位與核心理念】

cat5201 是一套以 Windows WPF（.NET 8，C#）開發的 AI 整合工作台。它的核心定位不是「又一個 AI 聊天介面」，而是「可以讓多個 AI 模型在同一個視覺化畫布上協作、並輸出完整成品的工作平台」。

傳統 AI 工具的使用流程是：先打開 ChatGPT 問問題 → 切換到 Perplexity 搜尋新聞 → 再切到 Midjourney 生圖 → 最後自己貼到 Word 排版。cat5201 把這整個流程壓縮在一個視窗內完成，並讓這些工具彼此知道對方做了什麼。

目標市場：需要多源整合並產出專業成品的知識工作者，包括金融分析師、商業顧問、內容創作者、研究人員。

目標時程：2026 年 9 月完成商用 MVP，具備可重複展示的完整 Demo 劇本。

開發者：單人開發（大學生），從 2026 年 5 月開始迭代，目前已累積 14 個已完成開發章節。


【二、技術架構概覽】

平台：Windows 11、.NET 8、WPF（XAML）
語言：C#
命名空間：test
主要進入點：MainWindow.xaml / MainWindow.xaml.cs

核心服務層：
- AgentRuntime：執行節點任務的主控制器，跑在 UI 執行緒（不可加 ConfigureAwait(false)）
- OrchestrationPlanner / OrchestrationStateMachine：任務分類與多階段執行規劃
- AiServiceRouter：依供應商 Kind 路由到正確的 AI 服務實作
- AiModelRegistry：所有模型定義、能力標籤、成本層級、可用狀態的集中登錄表
- NodeExecutionCoreService：節點層級的執行協調
- NodeContextService：收集上下游節點的 context，建立 ChainDirectiveContext
- NodePromptBuilder：組裝最終送給 AI 的 prompt，包含 ChainDirectiveHeader + PreferenceHeader
- NodeMemoryService：記憶讀寫、偏好管理、chain isolation 過濾
- MemoryStore：JSON 檔案持久化層

UI 層：
- MainWindow：主畫布，管理節點、連線、重繞（rewire）模式、個人化面板
- NodeControl：單一節點的 WPF UserControl，含輸入區、輸出區、狀態列、右鍵選單
- AgentWorkspace / AgentWorkspaceBuilder：工作區產出物（artifacts）的結構化儲存與顯示

資料持久化：
- WorkflowRunStore：每次執行歷史
- MemoryStore（JSON）：偏好與 episodic 記憶
- ApiKeyStore（Windows DPAPI 加密）：API 金鑰本機儲存

輸出路徑：所有生成檔案統一寫入 _generated/ 子目錄，檔名含時間戳。


【三、支援的 AI 供應商】

1. OpenAI（GPT 系列）
   - 主要用途：文字生成、圖片生成（gpt-image-2）
   - 服務類別：OpenAIChatService、OpenAIImageService
   - 成本層級：Economy（GPT-4o-mini）/ Standard（GPT-4o）/ Premium（GPT-4）

2. Anthropic（Claude 系列）
   - 主要用途：複雜推理、長文件分析、策略整合
   - 服務類別：ClaudeChatService
   - 模型：claude-haiku-4-5（Economy）、claude-sonnet-4-6（Standard）、claude-opus-4（Premium）
   - 備注：Claude Opus 受 Auto 成本保護限制，不在 Auto 模式自動觸發

3. Perplexity / Sonar
   - 主要用途：即時搜尋、新聞查詢、金融資訊
   - 服務類別：PerplexityService、PerplexitySonarService
   - 成本：深度搜尋每次約 NT$0.8，有搜尋額度限制

4. Google Gemini
   - 主要用途：長文、程式碼、Google 生態整合
   - 服務類別：GeminiChatService
   - 模型：gemini-2.5-flash（Economy）、gemini-2.5-pro（Standard）
   - 影片：Veo 3.1（透過 Gemini API）
   - 備注：2026-06-14 已正式啟用，金鑰有效

Fallback 邏輯：
- AiCapabilityGuard 依能力標籤 + 成本由便宜到貴自動切換
- AiFallbackPlanner 提供最後手段備援
- 所有 fallback 行為均記錄在決策窗（SetLiveDecisionExecuting）


【四、多代理協作架構】

核心概念：同一個節點內，Orchestrator 可以依照任務需求調度多個 AI 能力依序執行，最後整合成一份輸出。

OrchestrationTaskType（任務類型）：
- Research：研究型任務，觸發 research-first 管線
- Write：寫作型任務
- Summarize：摘要型任務
- GenerateFile：文件輸出型任務
- Media：多媒體生成任務（圖片/影片）
- Code：程式代理任務
- Workflow：工作流任務

Capability 執行順序（CapabilityOrder）：
- SearchCapability → CodeCapability → ImageGenerationCapability → VideoGenerationCapability → FileCapability

研究管線（Research-First Pipeline）：
1. Perplexity Sonar 搜尋最新資訊
2. 來源可信度評估與標記
3. Claude 整合多源事實並去重
4. 最終合成（Final Synthesis）產出完整回答

Workspace 產出物類型：
- facts：已查證事實
- draft：草稿
- validated：驗證完成
- exported：已輸出檔案
- failed：失敗

每個 artifact 帶有：SourceAgentId、ModelId、CapabilityId、NodeId、CreatedAtUtc、DependsOn、Preview


【五、視覺化節點工作流（Canvas）】

畫布由 MainWindow 管理，節點（NodeControl）以 Canvas 座標定位，節點間以 Connection 物件連線。

Connection 物件屬性：
- StartNode / EndNode：上下游節點
- StartThumb / EndThumb：連接孔（ThumbTL 左上、ThumbTR 右上）
- FlowMode：資料流向
- Path：畫面上的連接線路徑

節點狀態（NodeRunStatus）：
- Idle：閒置（黑框）
- Running：執行中（藍框 + 轉圈動畫）
- Success：成功（綠框，短暫提示後恢復黑框）
- Failed：失敗（紅框 + 重新執行鈕）

節點右鍵選單功能：
- 執行此節點
- 執行此節點與下游
- 加入記憶（手動將輸出加入全域記憶）
- 更換連接方向（視覺互換接孔，不影響上下游）
- 刪除節點

Rewire（更換上游）模式：
- 拖拉現有連線端點可切換上游節點
- 拖拉時顯示藍色虛線 ghost 路徑
- 放開在新節點的接孔上完成 rewire
- ESC 或拖放到空白處取消，恢復原連線

自動下游節點展開：
- 輸入任務後，系統自動生成研究節點、撰寫節點、輸出節點並串連
- DownstreamNodePlanBuilder 依任務類型建立展開計畫
- 每個展開節點使用 {{input}} 模板注入上游輸出
- 鏈可重播（RunManualWorkflowChainAsync）、可略過（SkipStepAndContinueAsync）、可停止


【六、記憶系統 v1】

記憶系統分為兩個主要軌道：

1. 偏好記憶（Preferences / user_preference）
   - 來源：僅限手動輸入（個人化面板）或右鍵「加入記憶」
   - 無被動自動擷取（2026-06-23 移除）
   - 排序：UpdatedAtUtc 由新到舊（最新偏好優先）
   - 衝突規則：節點自身輸入 > 上游鏈設定 > 全域偏好 > 系統預設

2. Episodic 記憶（execution_result / agent_result 等）
   - 來源：每次執行後自動記錄
   - 用途：供同一鏈的後續節點召回參考

記憶的優先級完整階梯：
   節點自身明確指定 ＞ 上游鏈設定（ChainDirectiveContext）＞ 全域偏好 ＞ 系統預設

Chain Isolation（鏈式隔離）：
   - 召回記憶時，只取同一鏈（BFS 祖先 + 後代）的 episodic 記憶
   - user_marked 類別的記憶不受 chain isolation 限制（全域可見）
   - GetSameChainNodeIds 以 BFS 收集同鏈節點 ID 集合

使用者標記記憶（user_marked）：
   - 右鍵節點 → 「加入記憶」觸發
   - SourceNodeId = 節點 ID，用於去重（同節點重複加入會取代舊的）
   - 顯示在個人化面板的「當前記憶」區塊
   - 清除記憶會同時清除偏好與 user_marked

ChainDirectiveContext（上游鏈設定）：
   - 由 NodeContextService.BuildChainDirectiveSection 建立
   - 從直接上游往更遠上游收集節點的 Top 文字
   - 最接近的上游標記「最優先」，放在 prompt 最前面
   - NodePromptBuilder.ChainDirectiveHeader 放在 PreferenceHeader 之上
   - 作用：語言、格式、語氣、風格等持續性設定會從上游延續到下游


【七、多媒體生成系統】

─── 圖片生成 ───

服務：OpenAIImageService（gpt-image-2）
觸發：輸入含有生圖相關關鍵字，或任務類型為 Media
輸出：寫入 _generated/.png
成本：高品質大圖約 NT$55/張（依尺寸/品質查表估算）
狀態：queued → generating → completed / failed
用途：獨立圖片輸出，或嵌入 PPTX 封面頁

圖片編輯：
- 上傳照片 + 指令 → OpenAIImageService.EditAsync
- 有圖片附件 + 編輯意圖 → ImageEdit，優先於影片意圖判斷

─── 影片生成 ───

主要供應商：Veo 3.1（Google，透過 Gemini API）
備用：FastCut 模式（多段獨立生成 + ffmpeg 拼接，不用延伸 API）
Sora：已停服，已移除

Veo 3.1 連貫模式（Continuous）：
- 基底 8 秒 base 影片（16:9）
- VeoVideoService.ExtendAsync 原生延伸，每段 +7 秒
- 最多 21 段延伸 = 148 秒
- 段數由 Claude 分鏡計畫決定（每 scene = 一段）
- 後段從前段最後畫面延續，要求重述主角/場景特徵保持一致

Veo 3.1 FastCut 模式：
- 預告片/快剪/混剪/MV/蒙太奇/trailer 等關鍵字觸發
- 每鏡頭獨立 4 秒 Veo base 生成
- FfmpegService.TrimAndConcatAsync 拼接（各裁 ~2.5 秒，H.264/yuv420p/24fps/1280x720）
- 最穩定，不依賴延伸 API
- 上限 6 鏡頭（成本控制）

影片成本（Veo 模型等級）：
- Standard：$0.40/秒（約 NT$12/秒）
- Fast：$0.15/秒
- Lite：$0.05/秒（預設，不支援延伸，Continuous 強制單段 8 秒）

電影風格提示詞（VideoStyle.DefaultCinematicPrompt）：
- 35mm 底片質感、淺景深、柔和光線、輕微顆粒
- 刻意不過度銳利，避免過度 AI 感
- 個人化頁面可自訂覆寫或一鍵恢復原廠

Claude 導演流程：
- 先產出結構化影片計畫（VideoPlanPayload）：劇本、分鏡、旁白、鏡頭、風格
- 核心計畫永遠執行（不需 Veo API 即可交付分鏡計畫）
- 主合成文字作為導演底本（treatment），避免計畫與實際影片不一致
- 導演 prompt 強化：禁止含文字/字幕/logo，聚焦單一主體，負面提示

ffmpeg 整合：
- FfmpegService 偵測：環境變數 CAT5201_FFMPEG → PATH → 常見安裝路徑 → WinGet Packages
- 未裝時 FastCut 自動降級 Continuous 並提示
- ffmpeg 8.1.1 已安裝（winget install Gyan.FFmpeg）

Veo API 已知問題（已修）：
- numberOfVideos 不可送（400 錯誤）
- 延伸 source 必須用 video.uri，不可用 inlineData
- 延伸來源需 16:9（9:16 直式會 400）
- 偶爾 done=true 但無影片內容（API 不穩，已加 raw response 診斷）

【九、成本控制系統】

Auto 模式成本保護：
- Auto 模式不自動觸發 Claude Opus 或 Perplexity Deep Search
- AiAutoCostPolicy 定義何種任務允許何種成本等級
- AiModelHelper 協助成本等級判斷

生成前費用估算：
- ModelCostEstimator.ImageCostUsd / ImageCostDisplay：依尺寸/品質查表估算圖片單張成本
- 影片計畫 note 顯示「預估成本 US$X（≈NT$X）」
- Token 成本：Claude/GPT/Perplexity/Gemini 四家都串回真實 API usage，決策窗顯示「實際 N tokens」

成本參考（2026 年 6 月）：
- Claude Haiku：NT$0.1 以下
- GPT-4o-mini：NT$0.05–0.15
- Claude Sonnet：NT$1–3
- Claude Opus：NT$3–15（受成本保護）
- Perplexity 深度搜尋：NT$0.8/次
- gpt-image-2 高品質：NT$55/張
- Veo 3.1 Standard：NT$12/秒

API 金鑰管理：
- ApiKeyStore：App 內設定頁直接輸入 OpenAI / Claude / Gemini / Perplexity 金鑰
- 存取順序：環境變數 → App 內輸入 → 自動切換 fallback → 全失敗回報
- 加密：Windows DPAPI（CurrentUser），本機加密，不上傳


【十、個人化系統】

設定頁分為兩分頁：
- 個人化：偏好設定、全域記憶管理、影片風格
- API：金鑰輸入

個人化資料儲存在 _preferences.json（與專案檔分離）

偏好項目：
- 輸出語言偏好
- 格式偏好
- 語氣/風格偏好
- VideoStyleOverride：影片風格自訂覆寫（空 = 使用原廠電影風格）
- VeoModelTier：影片模型等級（Standard/Fast/Lite）

全域偏好規則：
- 只能手動加入（個人化面板輸入 或 右鍵「加入記憶」）
- 不存在被動自動擷取
- 衝突時：節點輸入優先，偏好中最新加入者優先
- 上游鏈設定（語言/格式/語氣）可覆蓋全域偏好

OutputIntentResolver（輸出意圖判斷）：
- 用 LLM 判斷要產哪些檔案格式（單一真相來源）
- 不另外造分類器，所有多產檔 bug 修在它的 prompt


【十一、程式代理（Code Agent v1.5）】

目前能力：
- CodeContextExtractor：從程式碼庫擷取 anchor windows（目標函式前後文）
- CodeContextExtractor：chunk map（大型檔案分塊分析）
- CodeDiffDryRunValidator：驗證 AI 產出的 diff 是否可套用
- Repair loop：驗證失敗時自動要求 AI 修正 patch
- CodeTaskAssessor + BuildCodeRiskNoteBlock：大型任務風險評估與警告
- Bug listing / bug fix selected：先列出 bug 清單，再選擇其中一個修復

不支援（規劃後期）：
- Sandbox apply（直接在沙盒中套用 patch）
- Codex-like 完整專案自主修改


【十二、決策窗（Workspace / Decision Visualization）】

節點執行後可打開決策窗查看：
- 執行摘要卡：模式（手動/自動）、任務類型、記憶使用、產出數量、結果
- Memory 步驟：顯示本次召回的偏好 N 條、記憶 M 條，列出具體內容
- Orchestration 步驟：各 capability 執行狀態（pending/running/success/failed/skipped）
- Workspace 步驟：所有 artifact 卡片，含種類/格式/狀態/來源/依賴/Preview
- Model 步驟：使用模型、成本層級、能力標籤、實際 token 消耗
- Fallback 記錄：fallback 發生的原因和 attempt 序號

Artifact 卡片操作：
- 「💾 匯出」：純文字 artifact 寫成 .txt 並開啟；已落地檔案直接開啟
- 「📋 複製」：複製標題/類型/來源/依賴/預覽
- 右鍵選單：複製

【十六、已知限制與技術債】

1. WPF 桌面限制：Windows only，無雲端同步，無多用戶協作，觸達率受限
2. Orchestrator 的「多代理」是序列單節點，非真正並行多代理執行
3. Code Agent 距離 Codex-like 自主修改仍有差距
4. Memory v1 偏向「設定儲存」而非「學習」，尚未到「離不開」的深度
5. Veo 延伸 API 偶爾不穩（done=true 但無影片），FastCut 是更穩定替代
6. 功能廣度 > 深度，目前各功能都是 v1 或 v1.5 層級


【十七、核心競爭差異化】

vs 傳統 AI 工具（ChatGPT、Claude.ai、Perplexity）：
- 不需切換工具，多 AI 在同一畫布協作
- 直接輸出完整成品（PDF/PPTX/影片），不只是聊天回應

vs Microsoft Copilot / Google Gemini Workspace：
- 不綁定單一生態系，自由組合各家最強 API
- 視覺化工作流，可看到每步決策與花費

vs n8n / Zapier AI：
- 不需要預先設定 workflow，輸入自然語言即自動規劃
- 有 context 傳遞和記憶系統，不是無狀態自動化

真正的差異化（護城河）：
- 多供應商 + 可稽查工作流：每步的 AI 選擇、費用、產出物、來源都可查看
- 本機金鑰管理（DPAPI）：符合對資料敏感的企業/金融機構需求
- 研究事實驅動的輸出：輸出帶有來源標記，不是純 AI 幻想


【十八、關鍵設計原則（給未來開發參考）】

1. OutputIntentResolver 是輸出格式判斷的唯一真相，不另造分類器
2. AgentRuntime.ExecuteAsync 跑在 UI 執行緒，內部 await 不可加 ConfigureAwait(false)
3. 記憶只來自手動加入，不被動自動擷取偏好
4. 個人化設定以使用者為主，永不被系統覆蓋（_preferences.json 與專案檔分離）
5. 同鏈詳細共享，跨鏈只能大概知道，不可互相污染
6. 成本降級只看 Auto 開關，僅在 Auto 模式生效
7. 新模型加入只需在 AiModelRegistry 新增一筆，零核心改動
